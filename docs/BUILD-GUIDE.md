# Build guide

How games in this repo are built, so the next one matches Bank.

## What this is

A small static site of original tabletop helpers (scorekeepers, dice) from NordgrenLabs. Plain HTML, CSS and JavaScript: no build step, no npm, no framework, no TypeScript, no Tailwind. Any static host can serve it, any file opens in a browser as is, and there is nothing to upgrade or break. Keep it that way; if a game ever needs a server, that is a separate backend (see the decisions log), not a build step here.

## Layout

```
site/                    the published site, and nothing else
  index.html             games list
  style.css              shared: tokens, backdrop, glass, buttons, menu, sheets, segmented control, skeletons, tap feedback
  platform.js            shared: window.NL (saves and their outbox, identity, account control, theme, menu, segmented control)
  config.js              placeholder for the Worker's /config.js (Clerk publishable key); keeps the static preview signed out
  signin.html            the sign-in page the Worker serves in place of any page when there is no session; self-contained
  manifest.webmanifest   home-screen app: name, icons, colours
  apple-touch-icon.png   180px icon at the root, which iOS asks for even when a page has no tag
  favicon.ico            root favicon, likewise
  icons/                 favicon.svg, icon-192.png, icon-512.png (all made by brand/make_icon.py)
  _headers               response headers for the static files on Cloudflare (nosniff)
  bank/index.html        one game: its own CSS and JS inline
  dicelanes/             DiceLanes: index.html, engine/*.js reducer, ui/*.js screens, its own manifest.webmanifest and offline sw.js
  keep/                  Dusk Keep (working title): index.html, engine/*.js rules engine, ui/*.js screens, content/ slots and fixtures
server/                  the Worker (sign-in gate, /api and /config.js) and its tests
brand/                   the icon master (pinned by sha256) and make_icon.py, which writes every published size
migrations/              D1 schema, forward only
wrangler.jsonc           Cloudflare Worker configuration
tests/<game>/            node --test suites for games with module engines, outside the published site
tools/                   developer scripts, outside the published site (keep-content.js: the Dusk Keep content checker; keep-soak.js: its soak exposure counts; keep-scenario.js: prepared autosaves for checking rare Dusk Keep screens in a browser, `node tools/keep-scenario.js list`, then `node tools/keep-scenario.js <name>` prints the value for localStorage `nl-keep-v1` on stdout and what to do next on stderr)
docs/BUILD-GUIDE.md      this file
docs/content-kit/        the Dusk Keep content kit guide, for the owner writing original content
docs/decisions/          decision records (0001: platform adoption, 0002: Cloudflare hosting, 0003: sign-in required)
```

Only `site/` is ever published. Shared code lives only in `style.css` and `platform.js`. Everything game-specific (rules, screens, layout) stays inline in that game's `index.html`. Do not add a third shared file without a strong reason.

Exception: a game may keep its rules engine in plain ES module files under its folder (`<game>/engine/*.js`, with its screen code in `<game>/ui/*.js`, loaded with `<script type="module">`, no build) when the rules need tests under `node --test`; tests go in `tests/<game>/` at the repo root, outside the served site, and run with `node --test "tests/<game>/*.test.js"`. Bank stays inline. Dusk Keep and DiceLanes use the module layout.

## Design system

Apple-style minimalism: system fonts, frosted glass, light and dark, quiet motion.

- **Tokens** (`style.css`, `:root`): `--canvas --solid --ink --ink2 --accent --danger --good --primary --glass --glass-strong --edge --hair --fill --thumb --shadow`, fonts `--text` and `--num` (rounded, for numbers), and the spring `--spring` / `--spring-dur` (stiffness 400, damping 30, about 0.45s). Use tokens; do not hard-code colours.
- **Glass**: add `class="glass"` to a panel. Falls back to solid under `prefers-reduced-transparency`.
- **Buttons**: `.btn`, `.btn.primary` (full width, 54px), `.btn.danger`.
- **Menu**: `<nav class="menu">` fixed top right, holding a `.menu-trigger.glass` button (hamburger `.bars` and `.x` SVGs) and a `.menu-items` div of `.item.glass` buttons or links, each an inline 22px SVG (`stroke="currentColor"`) plus a `<span class="glass">` label chip. Call `NL.menu(nav)` once: it handles `aria-expanded`, `inert`, Esc, outside taps and closing on a choice; mark an item `data-keep-open` to keep the menu open after it. Bank instead has a round Undo button (`.undo.glass`, inside the nav, under the trigger) that is always one tap away during a game; its menu items open below it.
- **Sheets**: `<dialog class="sheet glass">` with a single inner `<div>`; open with `showModal()`. Close on backdrop click with `d.onclick = e => { if (e.target === d) d.close(); }`; Esc is native. Never use `alert()`, `confirm()` or `prompt()`: they are suppressed in some hosts.
- **Tap feedback**: shared, nothing to add. `platform.js` puts `.tapped` on any button, link or summary on pointerdown and keeps it about 350ms after the finger lifts, because `:active` ends too soon on touch; `style.css` darkens it with the `--tap` token. Disabled controls never get it.
- **Skeletons**: `.skeleton` (plus `.line` or `.button`) is a soft placeholder the size of what replaces it, with a shimmer that stops under reduced motion. Use one wherever data arrives late, mark its container `aria-busy`, and always resolve it to the content, an empty state or a short error with a retry.
- **Scroll bars** are hidden everywhere (`scrollbar-width: none` and `::-webkit-scrollbar`); scrolling itself is untouched.
- **Segmented control**: `<div class="segmented" role="group" aria-labelledby=...>` of `<button value=...>`. `const show = NL.segmented(group, value => ...)` wires it; call `show(value)` to mark the chosen one (sets `aria-pressed`, the thumb springs).
- **Theme**: `<html data-theme="light|dark">` holds the resolved theme; dark tokens apply under `:root[data-theme="dark"]` (with a `prefers-color-scheme` fallback when the attribute is missing). The preference `system|light|dark` is in localStorage `nl-games-theme`; `NL.theme.get()` and `NL.theme.set(p)` read and change it, and system follows the OS live. Every page needs the one-line no-flash script in `<head>` (copy it from `bank/index.html`) before the stylesheet. The Appearance control and its sun/moon icon markup are in Bank's settings sheet; the icon's CSS is `.theme-icon` in `style.css`.

Quality floor for every screen: visible keyboard focus, 44px touch targets, `prefers-reduced-motion` (global rule in `style.css`; also check it before any `element.animate()`), `prefers-reduced-transparency`, 375px wide with no horizontal scroll, light and dark both checked. Game pieces need at least 3:1 contrast against the panel they sit on in both themes, measured rather than eyeballed: Bank's white dice were about 1.1:1 on the light glass, so dice now use the `--die`, `--die-edge` and `--pip` tokens in `style.css` (dark dice with white pips in light, white dice with dark pips in dark). Check phones in landscape too (667x375), under `(orientation: landscape) and (max-height: 540px)`: keep content clear of the menu circle, sheets scroll, layouts respect `env(safe-area-inset-*)` on all four sides, and text inputs stay at 16px or larger so iOS does not zoom on focus. Copy is plain sentence case, no all-caps labels, no em dashes, no arrows on labels. User input (player names) goes in with `textContent`, never `innerHTML`.

## Per-game contract

1. **Rules are pure functions** with `console.assert` self-checks right under them (Bank: `applyRoll`, `standings`). No DOM in rule functions.
2. **All game actions go through `change(fn)`**, which pushes a snapshot to an undo history (capped) before mutating, then renders. Undo pops a snapshot.
3. **Autosave**: the whole game state is written to localStorage on every render under a versioned key (`nl-<game>-vN`). Bump N when the shape changes. Check the shape when reading it back.
4. **Saves via `NL.saves`** (all async): `list(game)` newest first, `get(id)`, `put(record)`, `remove(id)`. Record shape:

   ```
   { schemaVersion: 1, id: crypto.randomUUID(), game: "<game>", personPublicId: <uuid or null>,
     title: string, status: "in_progress" | "finished", createdAt: <ISO UTC>, updatedAt: <ISO UTC>,
     state: { ...owned by the game... } }
   ```

   camelCase, lowercase hyphenated UUIDs, ISO-8601 UTC, integer schema versions. `NL.saves` drops records that fail this shape; the game must also validate its own `state` before playing it (stored data is a trust boundary). Saving a resumed game reuses its `id` and `createdAt`. Keep a capped slice of undo history in `state` so undo survives resume.

   `put` always writes to this browser first and returns at once. For a signed-in person the server knows, those copies are an outbox: they are uploaded in the background, dropped only once the server holds them (or something newer), tagged with their owner so they only ever go into that person's account, and retried on the next load or when the network comes back. Saves made before any sign-in move to the first account. `list` returns the server's list with pending copies on top, each marked `pending` (`true`, or `'save_limit'`, `'too_large'` or `'refused'` when the server refused it); show those as not synced yet. `list` rejects when the server cannot be reached: keep showing what you had, never an invented empty list. `cached(game)` returns the last known list for this person at once, without the network, or `null` when nothing is known yet (show a skeleton). `remove` must reach the server when signed in, so it rejects offline: put the row back with a message. The window event `nl-saves` fires when an upload finished or was refused; refresh the list then. In the static preview, and for a signed-in person not linked yet, saves simply live in this browser.
5. **Identity via `NL.identity()`**: `{ displayName, personPublicId }` or `null`. When this browser has seen the person before it returns the cached name at once; otherwise it is `null` until `NL.ready` resolves, and `NL.settled` tells the two apart (show a placeholder while it is false). `displayName` can be empty. Pre-fill the first player only into an empty roster with no game in progress. `NL.person()` is whose saves this browser shows now (known from the session cookie before ClerkJS loads); stamp it on new saves and on the game's own autosave, and ignore an autosave from another person. Put `NL.account(el)` in the game's settings sheet: it shows the name and Sign out (there is no sign-in control on game pages any more, the Worker's sign-in page does that) and stays hidden without a key. Never store a Clerk user id or an email.

## Adding a game

1. Create `site/<game>/index.html`. Copy Bank's `<head>` (meta, no-flash script, `../style.css`) and its menu and settings sheet markup as a starting point. The `<head>` must carry the home-screen tags, with absolute paths: `<link rel="icon" href="/icons/favicon.svg" type="image/svg+xml">`, `<link rel="apple-touch-icon" href="/apple-touch-icon.png">`, `<link rel="manifest" href="/manifest.webmanifest">`, the `mobile-web-app-capable`, `apple-mobile-web-app-capable`, `apple-mobile-web-app-status-bar-style` (`black-translucent`, so keep content clear of `env(safe-area-inset-top)`) and `apple-mobile-web-app-title` ("Games") metas, and the light and dark `theme-color` metas. Without the manifest link the page still gets the icon from the root fallbacks but does not install as a standalone app.
2. Write the rules as pure functions with asserts. Design the rules yourself; games here must be original in everything expressive. When the owner asks for it, a game may instead implement the documented procedures of an existing tabletop game, with its content slots filled by the owner's original content (see "Original expression, faithful mechanics where asked" in the decisions log).
3. Hold state in one object, route actions through `change()`, autosave under `nl-<game>-v1`.
4. Wire `NL.menu`, sheets, `NL.segmented` and saves as above. Load `<script src="../config.js"></script>` then `<script src="../platform.js"></script>` before the game script.
5. Add a `.glass.tile` link to `site/index.html`.
6. Preview and run the checks below.

## Preview and checks

From the repo root: `python -m http.server 8765 --directory site`, then open http://localhost:8765/. It runs signed out with no gate. To run the Worker and the site together, with a local D1 and still no gate, use `cd server && npm run dev` and open http://localhost:8787/. To try the gate locally, run `wrangler dev` with a throwaway key pair passed as `--var` values and a synthetic `__session` cookie; never a real key.

Before calling it done:

- Console clean, no failed asserts.
- Play a full short game: every action, undo, reload mid-game restores it, save, resume, delete, a finished save.
- 375x812 and a wide window; light and dark; keyboard only; reduced motion on.
- Clear test data from localStorage afterwards.

## Server

Production is one Cloudflare Worker on the free plan (decision 0002). The Worker in `server/worker.js` runs first for every request (decision 0003): it answers `/api/*` and `/config.js` itself and serves `site/` through the `ASSETS` binding behind the sign-in gate. Pages and files need ClerkJS's `__session` cookie; the API needs the bearer token; both are verified offline in `server/seam.js` with the same pins (decision 6 of the adoption record). Only the manifest and the icons are public, by exact path. Protected files are sent `private, no-cache` so the browser revalidates cheaply (304) through the gate. Plain JavaScript modules, no build step of our own: wrangler bundles the Worker. Its only runtime dependency is `@clerk/backend`, and its only dev dependency is `wrangler`, both pinned exactly. `wrangler.jsonc` holds the three public Clerk values and nothing secret. The Worker answers 503 `misconfigured` if any other `CLERK_` variable is present or if only some of the three are set; all three empty is the signed-out `dev` environment.

Run the tests with `cd server && npm install && npm test`. They call the real Worker handler against a real local D1 and the real assets binding from wrangler's `getPlatformProxy()`, with a throwaway key pair; they need no network, no Cloudflare login and no real keys. `server/client.test.js` runs the real `site/platform.js` in a Node vm with only the browser's edges stubbed and `fetch` routed into the Worker, for the saves matrix (saving once, loading, deleting, switching accounts, two devices, limits and failures). `npm run check` adds a `wrangler deploy --dry-run`.

The saves API in `server/saves.js` backs the four `NL.saves` methods: `GET /api/saves?game=<game>` is `list`, `GET /api/saves/<id>` is `get`, `PUT /api/saves/<id>` is `put` and `DELETE /api/saves/<id>` is `remove`. Every save is keyed on the verified `nl_person_id`, so another person's save always answers 404, and the `personPublicId` a client sends is replaced with the verified one. Saves live in the D1 database `games` (schema in `migrations/`), and each person may keep 200 saves of at most 256 KB each. D1 has no interactive transactions, so every ownership or cap check sits in the same statement as the read or write it guards.

A new game folder under `site/` ships without any change to the Worker and is behind the gate from the start. Anything that must not be served at all stays outside `site/`. `docs/runbooks/deploy.md` has the release steps.

## Decisions log

- **Static, vanilla, no build.** Nothing to install or maintain; any static host works.
- **Storage behind an async adapter (`NL.saves`).** Written to this browser first, uploaded for a signed-in person, with no change to game code.
- **Sign-in required.** `docs/decisions/0003-sign-in-required.md` (2026-11-18): signed-out visitors see only the sign-in page; there is no signed-out play in production.
- **Icon.** A white die on navy, chosen by the owner. `brand/make_icon.py` writes every published size from the pinned master; never edit the PNGs by hand.
- **Control Center compatibility.** The Control Center (`C:\Projects\NordgrenLabs-Control-Center`) is Next.js 16, React 19, TypeScript and Tailwind 4 with Clerk. Platform rules live in `C:\Projects\NordgrenLabs-Platform` (NL-ADR-0002 to 0005, `docs/architecture/app-access-architecture.md`). Per those records: each app owns its own data and authorization; the Control Center never reads an app's database; apps are keyed on the `nl_person_id` claim (a UUID, `personPublicId` here), never the Clerk subject or email; apps must not hold a Clerk secret key; app hostnames follow `<app>.nordgrenlabs.com`.
- **Platform integration is built in this repo, not yet live.** `docs/decisions/0001-platform-adoption.md` (accepted 2026-11-18) records it: sign-in with ClerkJS on `games.nordgrenlabs.com`, a small backend in `server/` (now a Cloudflare Worker with D1, decision 0002) that verifies the session and implements the same `NL.saves` interface keyed on `nl_person_id`, and a Control Center catalog entry (anonymous play was kept then, and dropped by decision 0003). `docs/PLATFORM-INTEGRATION-PLAN.md` has the step list; deployment and the catalog entry are still to do, and real sign-in has not been exercised. Under the plain static preview everything runs signed-out and `NL.identity()` reads `window.NL_IDENTITY`. The client stays static with no build step throughout.
- **Hosted on Cloudflare, free plan only.** `docs/decisions/0002-cloudflare-hosting.md` (2026-11-18) moved Games from a container on the home VM to one Worker with static assets and D1, so the site stays up when the home connection drops. Any paid plan or any other Cloudflare product is a stop-and-ask for the owner.
- **Original expression, faithful mechanics where asked.** Games are original in everything expressive: names, art, characters, card and screen wording, map art, narrative. A game may implement the documented procedures of an existing tabletop game (turn structure, dice formulas, deck sizes, probabilities) in our own code when the owner asks for it, with its content slots filled by the owner's original content, never a transcription of a published set's cards, tiles, board or characters. Bank shares only folk rules; Dusk Keep follows this rule.
- **Bank specifics.** Saved games sit in a collapsed section with the count in its summary, remembered open or closed for the visit. Delete is two taps; the confirm state lasts until the second tap, a tap elsewhere or 4 seconds, not focus and blur, because Safari on iOS drops focus from a tapped button. Keypad keys are square in portrait; in phone landscape they take what fits under the Undo circle. Standings are always sorted (banked points, or "if banked now" as a setting); rank and gap always use banked points. Rows are keyed per player and slide into place (FLIP). In the live phase the 2 and 12 keys are disabled with the label "doubles" so players learn the Doubles key.
- **Dusk Keep specifics.** Working title for a 1 to 4 player hot-seat dungeon board game that implements a documented tabletop rule set in our own code. Its plan, rule matrix and decision register are in `docs/plans/dungeon-game-plan.md`. The engine is a deterministic reducer with a seeded PRNG stored in state, so every roll and draw is logged and replays exactly; the UI only renders `view(game, content, seat)`. Content (board, tiles, heroes, cards) is data in `site/keep/content/`: the full Start stays disabled until every slot holds approved owner-original content, and "Test with fixtures" plays on content marked NON-AUTHENTIC TEST DATA. The owner writes content with the content kit (`docs/content-kit/README.md`): one plain-data file per slot type in `site/keep/content/original/`, shipped as empty templates, checked with `node tools/keep-content.js check` (outside `site/`, no dependencies, reuses `schema.js`), and play-tested before the full Start unlocks with "Play-test my content", which layers the owner's entries over NON-AUTHENTIC fill-in under its own banner. Provisional rulings are named entries in the rules config, not code branches. Undo only reaches back over actions that revealed nothing. Saves and identity follow Bank: saved games show from `NL.saves.cached('keep')` at once (a skeleton while nothing is known), refresh from `list` and on `nl-saves`, mark pending rows as not synced, keep the shown list when `list` fails, and put a deleted row back when `remove` fails; the two-step delete uses a timer and outside taps, not blur. `nl-keep-v1` carries `owner: NL.person()` and another person's autosave is ignored; new saves are stamped with `NL.person()`. The first player is pre-filled from `NL.identity()` only into an empty roster with no game in progress, with a placeholder row until `NL.settled`. A finished game is never saved: when a saved game ends its record is removed (retried until the server has it, hidden from the list meanwhile), the results stay only in the local autosave until the player leaves, and the results exit is Return to menu (the title screen, where a new game is set up only when someone starts one) or Back to results. A save keeps the newest undo steps that fit in about 240 KB (the oldest go first, `fitHist` in `ui/undo.js`), to stay under the server's 256 KB. Focus is never left on `<body>`: after a card, sheet, Back or cover closes and the table re-renders, `refocus` in `ui/app.js` puts it on the cover's "I am X, show me" button, back on the map grid if it was there, else on the prompt's first control (its heading, `tabindex="-1"`, when the next input is a tap on the map), with `preventScroll` on phones; it does nothing while a dialog or cover holds the screen, so a card that opens next keeps focus. A result card's Continue stays disabled (Esc too) until its dice land and its lines show.
- **DiceLanes specifics.** An original lane-crossing dice game for one to five players, plan in `docs/plans/dicelanes-plan.md`. One scoresheet, two modes. Physical dice is a companion: a tap on a cell always crosses it off (never the big lane picker), on any player's sheet; penalties by tap; each lane shows ten numbers and one wider cell holding the last number with its lock (two crosses when crossed); that cell tapped below five marks closes a colour locked by someone off this device. Digital dice rolls six seeded dice, then everyone chooses at once on one device: anyone may pick the white sum, the active player may also pick one white plus one coloured die (applied after their white pick), picks stay tentative until that player taps End turn (cells a pick rules out show muted with a dashed ring, and tapping one swaps it in for what conflicts, per `cellChoice` in `engine/moves.js`), the active player may tick a penalty box any time while choosing and must end the turn with a pick or a penalty, never both (ticking clears their picks, a pick unticks it; others never take penalties); a tentative X is drawn like a white die for the white sum, in the lane colour for white plus colour, and the roll resolves when everyone has ended their turn (marks, every colour locked on that roll closes, the ticked penalty, the end check), then the next player may roll. The engine is a serialisable reducer (`reduce(state, action)` returns the same object when an action is illegal; actions `mark`, `penalty`, `close`, `roll`, `choose` (a tap on a cell), `pick`, `unpick`, `done`) with the PRNG in state, so undo then roll gives the same dice. Undo keeps whole-state snapshots (200 while playing, 60 in a save), one change at a time (a pick, a Done, a resolve), and steps back from the results too. `nl-dicelanes-v1` carries `owner`; another person's autosave is ignored. Navigation is Bank's menu circle with the Undo circle under it. In a game the menu reads Scores, Exit, New game, Restart, Rules, Settings; the start screen shows Games, Rules, Settings. Exit is Bank's End game sheet; New game is a sheet (save and start new, start new without saving, keep playing) that starts a fresh game with the same players and mode; Restart takes two taps mid-game (`data-keep-open`). With digital dice the dice tray is the top element, with the two circles to its right and the chips under it; with your own dice the chips sit at the top beside the circles. In phone landscape and from 1040px wide the tray moves to a right column, still clear of the circles. It has its own `manifest.webmanifest` (linked with `crossorigin="use-credentials"`, since the Worker gates it) and `sw.js` (scope `/dicelanes/`, cache first with background refresh; bump `VERSION` on every release so phones pick up new files). Dice show only their front face once settled, so no edge line or seam shows; each die remembers its angles and a roll turns on from where it rests to the new face's pose plus whole turns, so it never snaps to the new face first. A per-device setting (Scores: While playing, At the end) hides every running score until the game is over. Every finished game opens on a finish list that is also the ranking: one row per player (rank, name, score line), counted up one column at a time for everyone (1 s a column, the counting box white, the rest grey), the rows re-sorting by the score so far in the 0.5 s beat after each column (FLIP), then the winner glows; tap or Skip jumps to the end, reduced motion shows it at once, and a reload shows the final state without replaying.
